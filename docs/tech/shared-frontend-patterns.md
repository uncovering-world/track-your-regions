# Shared Frontend Patterns — Reference

Quick-reference for reusable components and utilities. Use these instead of writing inline equivalents.

## Shared Components (`frontend/src/components/shared/`)

| Component | Purpose | Example |
|-----------|---------|---------|
| `LoadingSpinner` | Centered `CircularProgress`. Props: `size?`, `padding?` | `<LoadingSpinner />` |
| `EmptyState` | "No items" message. Props: `message`, `padding?` | `<EmptyState message="No results." />` |
| `ImageCreditLine` | Who took the picture above it, and under what licence. Props: `credit` (`experience.image_credit` / `treasure.image_credit`), `redundantWith?` — the maker or makers a dense row already names, which suppresses the line where it would only repeat one of them under a licence asking nothing; a list is matched against *every* name, since a work carries all of them (`creditAddsBeyond`, also exported), and `color?` — pass `inherit` on a dark surface such as a MUI `Tooltip`, where the default `text.secondary` is unreadable. Renders nothing when the source named nobody, and links only `http(s)` URLs. Also exports `creditLabel()`, the same credit as a text fragment for somewhere a component cannot go — a tooltip `title` | `<ImageCreditLine credit={x.image_credit} redundantWith={work.artists} />` |
| `CurationDialog` | Edit + reject/unreject an experience, and take a lifecycle verdict back (`former` / `lost`) — an answered object has left the review queue's open questions, and an object stays reachable at its own address, so this is where the way back lives. The queue keeps a collapsed list only for the two answers nothing else can reach: a refusal a curator confirmed, and a verdict on a *point*. Its History panel is also the one screen a verdict's note is readable on — a point's, the object's own, and the one on a rule's refusal — since taking a verdict back moves the row's note with the answer it explained. What those entries read as is `curationLog.ts`, not this file | Used in Map and Discover modes |
| `AddExperienceDialog` | Search+assign or create new experience | Used in Map and Discover modes |
| `curationLog.ts` | What one row of `experience_curation_log` reads as: `ACTION_LABELS` (a chip's words and colour per action) and `formatLogDetails` (the line under it — a curator's note, the fields a publication applied, the value taken from the source). Not a component, and deliberately not inside `CurationDialog`: the admin panel's curator-activity chip reads its words from here too, and the cross-curator feed (#611) is to render the same rows. Its test reads the action CHECK out of `db/init/01-schema.sql`, so an action the database accepts cannot go unnamed on screen | `ACTION_LABELS[entry.action]`, `formatLogDetails(entry)` |
| `LocationPicker` | Interactive location selector on a map | Used in experience editing |
| `MapUnavailable` | Explains that this browser cannot draw maps. Props: `detail?`, `compact?` | `<MapUnavailable detail="The list still works." />` |
| `LifecycleChip` | Labels a `former` or `lost` experience, nothing for an ordinary one. Props: `state` (`source_membership` / `existence`). Also exports `lifecycleLabel()` and `verdictOf()`, which share the precedence rule: existence answers first | `<LifecycleChip state={experience} />` |
| `GuardedMap` | `react-map-gl`'s `<Map>` with the WebGL check built in. Extra props: `unavailableDetail?`, `unavailableCompact?` | `import { GuardedMap as MapGL } from '…/GuardedMap'` — alias it to the local name and nothing else changes |
| `VirtualRow` | One row of a windowed list: places it where the virtualiser says and registers it with `measureElement`. Props: `virtualizer`, `index`, `start`, `children`. Renders a `li` — put it inside a `List` | Both windowed experience lists (`ExperienceList.tsx`, `discover/DiscoverExperienceList.tsx`) |

## Utility Modules (`frontend/src/utils/`)

| Module | Key exports |
|--------|-------------|
| `appUrl.ts` | `parseAppUrl(pathname, search)`, `buildAppUrl(address, names?)`, `legacyRedirect()`, `slugify()`, `slugsOf()` — the app's URL grammar, parse and build together with a round-trip test. Reach for it through `useAppAddress()` (`{ address, go }`) rather than `useSearchParams`/`navigate`: `go` decides push vs replace and keeps the slugs a write does not rename. See [addresses.md](addresses.md) |
| `categoryColors.ts` | Category color mapping, `VISITED_GREEN` (`#22c55e`), `PARTIAL_AMBER` (`#F59E0B`) |
| `dateFormat.ts` | `formatRelativeTime()`, `formatDuration(start, end)` |
| `imageUrl.ts` | `toThumbnailUrl()`, `extractImageUrl()` — the only two functions that decide what a picture's `src` may be. Both answer emptily (`''` / `null`) for a host outside the trusted list **and** for anything that is not an absolute http(s) url or a path that stays on our own origin — `javascript:`, `data:`, `blob:` and their kin, and `/\host/x`, which a browser reads as `//host/x`. Never put a stored `image_url` — or a region's imported map, `regionMapUrl` — into a `src` without one of them; `backend/src/types/urlSafety.test.ts` reads every component and fails on a `src` expression — a JSX `src={…}` or an imperative `img.src = …` — that names `regionMapUrl` or a record's `image_url` without calling one of the two (or `cardImageUrl`, which is built on both), or that sizes a url by hand (`${url}?width=500`, which is how seven admin dialogs used to draw the map, #694) — looking through one binding, so `const mapSrc = regionMapUrl; … src={mapSrc}` fails too. It pins those shapes and no more: the camelCase `imageUrl` is outside it, because under that name the tree holds prepared values as often as stored ones (the overlay's FileReader data url, the hover store's ready thumbnail), and so is a second level of indirection. They are not interchangeable, though: an experience's value goes through `extractImageUrl` **first**, because only it decodes the legacy `{"url": …}` form and turns a `/images/…` path into one on our API — handed that JSON string, `toThumbnailUrl` answers `''` and the picture silently disappears. `toThumbnailUrl` still checks for itself, since several callers hand it a raw value |
| `safeHref.ts` | `safeHref(value)` — the function that decides what a stored link's `href` may be: an absolute http(s) url, in the form the parser read, or `null` for everything else — `javascript:`, `data:`, `blob:`, a relative path that would resolve against this site, a value that is no url at all. Lifted out of `ImageCreditLine` (a credit's licence and details links) when a region's source page needed the same answer (#703); an experience's website and Wikipedia links do not ask it yet (#708). Never put a stored `sourceUrl` into an `href` or a `window.open` without it, and bind the answer to a name the JSX reads (`const href = safeHref(value); … {href && <a href={href}>}`): `backend/src/types/urlSafety.test.ts` reads every module (`.ts` and `.tsx`) that carries `sourceUrl` or a credit's `licenseUrl` / `detailsUrl` and fails on a dynamic `href={…}`, a `window.open(…)` or a `.href = …` assignment whose expression is anything but a `safeHref(…)` call or a url the file spells itself (a string literal, or a template opening on `https://` — the Wikidata link in `ImportTreeDialogs.tsx` is one) — `safeHref(x) \|\| x` hands the refused value straight back and counts as raw — looked at through one binding, with a name the file binds to nothing counting as raw, since the value reaches a link through a prop as often as directly. React blocks a `javascript:` href on its own; it does not block `data:`, and it does not touch `window.open` |
| `imagePreload.ts` | `cardImageUrl(rawImageUrl)` — the thumbnail an expanded experience card renders, so a preloader and the card cannot ask for different files; `preloadCardImage(rawImageUrl)`, `preloadImage(url)` — fetch it early and remember the answer for the session, failures included, so a url that 404s is never asked twice; `isImagePreloaded(url)` — *can I draw this picture?* (loaded); `isImageSettled(url)` — *is the answer known?* (loaded **or** refused). Ask the second when deciding whether something may be shown at its final size: four of these urls in five never resolve, and reading a known refusal as "still coming" makes a card wait for nothing |
| `queryInvalidation.ts` | `invalidateExperiences(queryClient, opts?)`, `invalidateAfterBatchPublication(queryClient)`, `invalidateVisitedStatus(queryClient)` |
| `scrollUtils.ts` | `scrollToCenter(container, el)`, `scrollToTop(container, el)` |
| `dangerLabel.ts` | `inDangerLabel(dangerSince)` — what the "In Danger" badge says. Use it instead of a literal `"In Danger"`: the listing is dated (`danger_since`, read on the server out of UNESCO's `"Y 2013"`), and the year is what the badge means on the ground. Optional as well as nullable — an absent field reads as the plain badge rather than "since undefined" |
| `locationLabel.ts` | `locationLabel(location)` — what to call one of an experience's points. Use it instead of `` `Location ${loc.ordinal + 1}` ``: `ordinal` is nullable (a point whose replacement is waiting to be published has no place in the source's list), and `null + 1` is `1`, which is the label a curator-created first point already carries |
| `coordinateParser.ts` | Coordinate string parsing |
| `mapUtils.ts` | `frameGeoJson(map, geojson, opts)` — **the one camera call for a shape a surface holds**: measures with `focusFromGeoJson`, flies with `smartFitBounds`, does nothing for an empty shape; takes a react-map-gl ref or the MapLibre map itself, with `padding`, `duration`, a `maxZoom` that can only lower the size-derived cap, and a `minZoom` floor of 0 — a shape a surface holds may be world-scale on purpose, so it fits what it was asked to show (#672). `smartFitBounds(map, bbox, opts)` — fly to a box you already have, handling the `west > east` crossing convention; pass `anchorPoint`, because MapLibre's `cameraForBounds()` does not handle a crossing box on its own — this is how a stored region's or division's `focusBbox` is framed, and its `minZoom` floor is 1, because one region framed at zoom 0 is the globe. `focusFromGeoJson(geojson)` → `{ bbox, anchorPoint } \| null` — measure a shape that exists only in the client (a boundary being drawn, a cut, a combined selection) the way `geometry_focus()` measures a stored one: keeps the tighter of the plain and shifted measurements, so a shape over the dateline comes back as a window rather than the world, and one that really wraps the world keeps its full-width box. A stored region or division carries its box already — read `focusBbox`, do not measure |
| `plural.ts` | `plural(n, noun)` — `"1 point"`, `"12 works"`. The count leads, because it is the judgement |
| `creatorList.ts` | Who made a work, as a sentence. `creators(names)` — `"Ivan Shishkin and Konstantin Savitsky"`, every name, for a surface with room. `creatorsBrief(names, confirmed)` — two names whole either way, and past two `"6 artists"` until a curator has claimed the order, `"Andy Warhol and 5 others"` once they have: the stored order is a query planner's, so leading with a name is a claim only somebody can make (ADR-0040). Both answer `null` where nobody is recorded, so a caller leaves the line out |
| `worldViewList.ts` | `worldViewList(failed)` — the world views a re-placement failed for, named for the curator and numbered for the admin. Handles the `id: null` shape that means listing them failed |
| `wordDiff.ts` | `wordDiff(before, after)` — which words differ between two versions of a text, as parts that reassemble into each side exactly. Refuses values past 400 words (`capped`) rather than freezing the tab; marks nothing that would change a decision, since both values render in full either way |
| `webgl.ts` | `isWebGLAvailable()` — ask before constructing any map; see `maplibre-patterns.md` |
| `viewBounds.ts` | `ViewBounds`, `pointInView(lng, lat, bounds)` — is this place on screen? Reads the box in its own frame, so it answers both MapLibre's unwrapped `getBounds()` shape (`{west: 175, east: 185}` over the dateline) and this repository's `west > east` one (`focus_bbox`, the `bbox` parameter) |
| `fetchUtils.ts` (in `frontend/src/api/`, not `utils/`) | `ensureFreshToken()` — proactive JWT refresh before SSE connections, **best-effort**: hands back whatever token it has when the refresh fails, spent or not, because the stream fails the same way either way. `requireFreshToken()` — the strict one: `null` for a *spent* token, so a caller can say "your session is over" rather than send a dead token; a merely expiring one it still hands over, since a failed refresh proves nothing |

## Pattern Table: Use This, Not That

| Need | Use this | Instead of |
|------|----------|------------|
| Read or write the app's place | `useAppAddress()` → `{ address, go }` | `useSearchParams()` / `useNavigate()`. `go` builds the URL from one grammar, no-ops on the address the page is already at, pushes what the visitor did and replaces what the app corrected, and keeps the slugs of ids it is not renaming. Hand-writing a path drops one of those every time — usually the slug of the id you were not thinking about |
| Loading spinner | `<LoadingSpinner />` | Inline `<Box sx={{display:'flex', justifyContent:'center'}}><CircularProgress /></Box>` |
| Preload a card's picture | `preloadCardImage(exp.image_url)` | `new Image()` on `extractImageUrl(exp.image_url)` — that is the *original*, which no surface renders (every one uses a `toThumbnailUrl()` size), and it neither remembers failures nor knows that four urls in five answer 403 |
| Empty state message | `<EmptyState message="..." />` | Inline `<Typography color="text.secondary">No items.</Typography>` |
| A link to a stored url (a region's source page, a credit's licence) | `const href = safeHref(value)`, then `{href && <a href={href} …>}` — or plain text where the name still means something without the link | `href={node.sourceUrl}` or `window.open(node.sourceUrl)`: the value is what an import tree posted, and a `javascript:` url runs on click. `urlSafety.test.ts` fails on both shapes |
| Who made a work | `creators(work.artists)` on a card or a dialog, `creatorsBrief(work.artists, work.artistsCurated)` on a row or a tile — the flag is `artists_curated` on `ExperienceTreasure`, which is served straight from the column, and `artistsCurated` on the shapes the queue builds | `work.artists[0]`, or `.join(', ')`. The first name alone is the bug ADR-0040 exists to close — it told a reader Savitsky painted the pine forest — and a bare join gives a tile a three-line row and a card a list with no "and" in it. Dropping the second argument is its own bug: the row then names a query planner's pick as the artist who led six |
| A credit under a picture | `<ImageCreditLine credit={x.image_credit} />`, plus `redundantWith` on a dense row, `color="inherit"` on a dark surface, and an `onError` that hides the credit with the picture | Nothing at all — which is what every surface did until 2026-08-22, while showing photographs whose licences require the author to be named. Dropping any of the three is the same failure in miniature: a list that repeats "Rembrandt · Public domain" under a row already reading Rembrandt, a credit painted near-black inside a tooltip, or — the one the row above makes ordinary — a photographer named under a frame whose picture answered 403. Hold the failure as *which URL* failed rather than as a flag wherever the component outlives one picture |
| A visible keyboard focus | Nothing — the theme's `MuiButtonBase` override carries it, and `focusRing.test.tsx` pins it | Your own `'&.Mui-focusVisible'` block. `ButtonBase` clears the browser's outline (`outline: 0`) and leaves `focusRipple` off, so **every** control built on it needs a ring; writing one per component is how this ended up in four places at once, and how the fifth gets forgotten. Note the form: the callback goes on the **slot** (`root: ({ theme }) => …`), never on a rule nested inside it — MUI resolves functions one level down only, and a nested one is dropped without a word |
| A control that is not a `<button>` | `<ButtonBase component="div" onClick=…>`, named by whichever of these fits: **visible text** where it has some, `aria-label` where it has none, `aria-expanded` where it discloses something | `<Box onClick>`. A div takes no focus and fires on no key, so the action exists for a mouse alone — `jsx-a11y` is not installed here, so nothing says so. And do **not** add an `aria-label` to a control that already reads "Show all 122 works": the label *replaces* the visible text as the accessible name, so a voice-control user saying "click show all works" reaches nothing (WCAG 2.5.3). Where there is no text to work with — a bare picture — name it by what the press will *do* and flip that name with the state, as `ContentTile` does; where the control opens something, `aria-expanded` is what carries the state, as both disclosure headers do |
| Visited green color | `VISITED_GREEN` constant | Hardcoded `'#22c55e'` or `'#10B981'` |
| Partial/amber color | `PARTIAL_AMBER` constant | Hardcoded `'#F59E0B'` |
| Invalidate experience caches | `invalidateExperiences(qc, opts)` | Manual chain of `queryClient.invalidateQueries(...)` |
| Invalidate after publishing a whole source | `invalidateAfterBatchPublication(qc)` | `invalidateExperiences(qc)` with nothing named — which reaches no object keys **by design**, so a batch would leave pins and queue cards stale |
| Invalidate visited caches | `invalidateVisitedStatus(qc)` | Manual invalidation of 3+ query keys |
| Scroll element to center | `scrollToCenter(container, el)` | Manual `getBoundingClientRect()` + `scrollTo()` |
| Label a `former` / `lost` experience | `<LifecycleChip state={experience} />` | Reading `existence` / `source_membership` inline, which drops the precedence rule — a row that is both must read `Lost`, since that is what hides it |
| Decide which verdict a row carries | `verdictOf(experience)` | Re-deriving it beside a lifecycle write, which is how the precedence rule ends up stated twice and drifting |
| Scroll element to top | `scrollToTop(container, el)` | Manual scroll math |
| Say a site is in danger, and since when | `inDangerLabel(experience.danger_since)` | A literal `"In Danger"`, which drops the year the listing carries. The badge is dated on the server (`danger_since`, read out of UNESCO's `"Y 2013"`) and the date is most of what it means on the ground: the Ancient City of Aleppo has been on that list since 2013, which is a thirteen-year emergency rather than a label. The field is optional as well as nullable, so a check written against `null` alone renders "In Danger since undefined" for a payload that omits it |
| Say "N things" | `plural(n, noun)` | **Any suffix computed from the count inline** — `n === 1 ? '' : 's'`, `n !== 1 ? 's' : ''`, `n > 1 ? 's' : ''`, in a template or in JSX. One sweep target, but **not one behaviour**: `> 1` reads "0 thing" at zero where the other two read "0 things", so replacing those is a fix and not a no-op, and each needs checking for whether zero can reach it. The `=== 1` form is right until a count arrives uncast from `COUNT(*)` and `'1' === 1` is false. 28 inline sites stand as of 2026-08-16 — 19 `!== 1`, 9 `> 1` — tracked in [#546](https://github.com/uncovering-world/track-your-regions/issues/546) |
| Name the world views a placement failed for | `worldViewList(failed)` | An inline `.map()` over `placementFailedWorldViews` — which renders "world view null" for the shape that means listing them failed, in the sentence a curator hands to an admin |
| Show which words differ between two versions of a text | `wordDiff(before, after)` | Truncating either side, or rendering them plain and leaving the reader to spot the change — which is what made a 200-character edit against 511 characters of source text unanswerable |
| Format duration | `formatDuration(start, end)` | Inline ms-to-seconds/minutes conversion |
| Fold an object's places to one pin | `useCollapsedExperiences(regionId)` + `<FoldPlacesControl />` | Local `useState` in a surface, or an effect that clears the set when the region changes — an effect runs after render, which leaves a commit where the new region's rows are drawn against the old region's folds |
| Rendering any map | `GuardedMap` (aliased to your local name), or an early return on `isWebGLAvailable()` where overlays sit over the map | Importing `Map` straight from `react-map-gl/maplibre`, or a bare `new maplibregl.Map` — both throw without WebGL, and there is no error boundary to catch it |
| Frame a shape a surface holds (a preview, a drawn boundary, a set of places) | `frameGeoJson(map, geojson, { padding, duration })`. A region or a division has `focusBbox` and `anchorPoint` stored and served — frame those with `smartFitBounds` and measure nothing (#674) | `turf.bbox` + `fitBounds`, a `Math.min` over the longitudes, a `LngLatBounds` extended point by point, or `initialViewState.bounds` — all the extremes of the raw longitudes, so a shape over the dateline comes back as `[-180, …, 180]` and the map frames the whole Earth at zoom 1 with the shape cut in two against the edges (#666, #672). `regionFocusAntimeridian.test.ts` fails on any of them |
| Ask whether a place is inside the map's view | `pointInView(lng, lat, bounds)` | `bounds.contains([lng, lat])`, or a literal `west <= lng && lng <= east` — `LngLatBounds.contains` takes its wrapping branch only on `sw.lng > ne.lng`, which `getBounds()` never produces, so both drop every real longitude over the dateline |
| Place a windowed list's row | `<VirtualRow virtualizer={v} index={i} start={row.start}>…</VirtualRow>` | A hand-rolled absolutely-positioned `Box` with its own `measureElement` ref — whose inline ref function detaches and reattaches per render, forcing a synchronous layout per mounted row (see the note in `VirtualRow.tsx`) |
| Share hover state between a list and a map | A store + selectors: `useHoverContext` (experiences/places), `useRegionHover` (regions) | React state in a context — every consumer re-renders per mouse move; `hoverStore.test.tsx` / `regionHoverStore.test.tsx` pin what a hover may re-render |
| Report New-badge impressions from a windowed list | `useSeenWindowIds(idsInVisibleRange, resetKey)` and hand the accumulated set to `useNewBadgeImpressions` | Reporting the fetched/filtered set — rows the window never held get stamped, and the server keeps the *first* impression, so their "new" week is spent unseen |
| Get a token for a request whose endpoint answers 401 for a reason of its own | `requireFreshToken()` — `null` for a spent token, so "your session is over" is decided before the request and never confused with what the endpoint meant. Note what it does *not* refuse: a token merely inside the 60s refresh margin still goes, because `refreshSession()` returns `null` for a 429 and a network blip as readily as for a rejected refresh, and treating that as a dead session signs people out of live ones | `ensureFreshToken()`, which hands back a dead token as readily as a live one — right for its SSE callers, whose stream fails the same way either way, and wrong for anyone who needs to tell the two apart. Which is which depends on the caller, so the pair is two names rather than one contract read two ways — `fetchUtils.token.test.ts` pins where they part |

## Maintaining This Doc

After extracting a new shared component or utility, add it here:
1. Add a row to the appropriate table above
2. Add a "use this / instead of" row to the pattern table
3. Link from the dev guide if a new concept is involved
