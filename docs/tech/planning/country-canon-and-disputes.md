## Решения сессий 2026-07-17/18

| Вопрос | Решение | Почему |
|--------|---------|--------|
| Механика споров в v1 | **Юзер решает + пресеты.** Личные выборы per-территория — единственная истина подсчёта; пресет = предзаполнение этих выборов одним кликом. | Дёшево (одна таблица префов, ни resolver'а, ни новой оси в запросах), максимально нейтрально, и данные пресетов — будущий сид настоящих перспектив: дверь не закрывается. | Куда в модель | **Новый глобальный слой рядом** с существующим; канон — НЕ world view. | Форма конечной архитектуры: канон один на всё приложение, виды позже собираются поверх; regions мутабельны и видо-скоуплены — класть туда опору нельзя (ловушка «родителя в строке»). |
| Дефолт для нового юзера | Пресет **`de_facto`** (кто фактически контролирует), явно показан и меняем. | Конвенция Natural Earth / наименее неожиданные числа из коробки; строгая нейтральность доступна пресетом `strict_neutral`. |
| Происхождение канона (2026-07-18) | **Динамический деривиатив по опубликованным правилам** из открытых источников (ISO 3166-1, списки ООН, Wikidata CC0, Natural Earth PD). Список **не коммитится** — в репе только правила (код) и документированные исключения; данные тянутся сборкой, provenance хранится в БД. | Требование Николая: юзеру можно объяснить, откуда список и как составлен; «список не наш — мы его выводим» = нейтральность бесплатно (вывод стратегического ревью про внешние списки). |
| Независимость от источника единиц (2026-07-18) | Канон ссылается только на внутренние id `administrative_divisions` («источник единиц»; сейчас GADM per ADR-0002, сменяем). Crosswalk и приземление споров — **геометрические правила**, пересобираемые при смене источника. | GADM — текущая реализация «наименьших админ-единиц», не контракт. Смена источника не должна трогать канон-записи, префы юзеров и статистику. |

## Инварианты

- **Пользователь отмечает реальность один раз; выбор линзы меняет только его
  счётчики.** Префы не трогают ни хранимые отметки, ни данные канона.
- **Карта нейтральна всегда**: спорные территории заштрихованы для всех
  пользователей без исключений; формулировки «принадлежит X» в UI нет нигде —
  только «считается как… (твоя настройка)».
- **Канон глобален, выводим и не хранится в репе**: содержимое — вывод из
  открытых источников по опубликованным правилам, выполняемый сборкой
  (sync-сервис); правка = изменение правил/исключений или новая сборка с
  диффом. Никакого редактирования канона мышкой и никакого членства «потому
  что мы так решили».
- **Канон не знает про GADM**: все ссылки — на внутренние id единиц;
  «источник единиц» — сменяемая реализация (сейчас GADM). Всё
  источнико-специфичное (матчинг корневых единиц, приземление споров)
  выражено пересобираемыми правилами, не данными канона.
- **Канон состоит не только из стран**: хребет — множество счётных
  сущностей, где страны лишь самый крупный класс (рядом — Антарктида,
  terra nullius). Требования к записи: есть экстент и она либо лист, либо
  имеет собственное L3. Подробности — инкремент 2026-07-25.
- Существующие `world_views`/`regions`/import-review работают как работали;
  новый слой ни одной существующей таблицы не меняет.

## Связь с world views и трёхуровневой схемой (L1/L2/L3)

Трёхуровневая рамка из
[world-view-levels-and-perspectives.md](world-view-levels-and-perspectives.md)
**соблюдается**: канон — это уровень L2, вынутый вперёд и построенный в его
конечной форме из
[world-view-workflow-rethink.md](world-view-workflow-rethink.md) («страны —
общая опора; надстрановые иерархии сверху, схемы деления снизу; уровни — это
положение дерева относительно страны»). Т.е. L2 — не роль узла внутри каждого
вида, а **один глобальный слой, который все виды разделяют**. Это ровно шаг 1
layered ingestion из umbrella-дока: «seed L2 country canon ← authoritative
source [ANCHOR]», и ровно стадия ① рекомендованного порядка сборки
(① страны + споры → ② надстрановое → ③ субнациональное).

Как уровни стыкуются с каноном (следующие шаги, не этот):

| Уровень | Что это после канона | Стыковка |
|---------|----------------------|----------|
| **L2 (страны)** | Сам канон: реестр + классы + споры + префы | Состав L2 любого вида = выборка из канона (фильтр классов × префы юзера). «The set of countries is perspective-dependent» из umbrella-дока стало «prefs-dependent» |
| **L1 (над)** | Надстрановые иерархии (континенты, UN M49, культурные) | Деревья, чьи **листья — ссылки на канон-страны** (`country_id`), не freeform-регионы. Импорт L1 = матчинг имён против готового канона (umbrella: «L1 matches country names against a ready canon»). Groupings ссылаются на страны/единицы так же |
| **L3 (под)** | Схемы деления страны | Схема привязывается к канон-записи (`country_id`); рамка покрытия — её `country_divisions`. Per-country workspace из import-review — готовая L3-петля |

**Вид (world view) = сборка** (по rethink-доку): надстрановая иерархия × схемы
деления. Одно отличие от rethink: **политика выпала из сборки** — там вид
включал перспективу, теперь споры разрешаются личными префами юзера глобально,
поверх любого вида. Вид отвечает за нарезку, юзер — за политику.

Следствия для существующего кода и POC (ничего не ломается):

- **Plan-1a (`level` из `is_work_unit`)** остаётся верным для legacy-видов;
  в целевой модели узел уровня `country` определяется ссылкой `country_id` на
  канон (derive-подход 1a форвард-совместим: сначала флаг, потом ссылка).
- **POC slice 1 (LevelSwitcher-шелл)** остаётся рамкой: вкладка L2 в будущем
  показывает канон и споры, L1 — группировку канон-стран, L3 — существующий
  workspace.
- **POC slice 2 (L1-редактор групп)** — его client-side группы над dashboard
  units в будущем становятся группами над канон-странами с персистенсом.
- **POC slice 3 (mini POV axis)** в исходной форме (perspectives + rulings +
  resolver) **не делается** — его заменяет этот документ (канон + user-decides
  + пресеты). Это осознанная замена по рекомендации стратегического ревью, не
  забытый кусок.
- Существующие виды (GADM, Wikivoyage-импорты) живут как legacy-деревья;
  новые виды собираются поверх канона по мере появления L1/L3 слоёв
  («новое рядом со старым», решение №7 сессии 24.06).

## Модель данных (скетч; точный DDL — в плане реализации)

```sql
CREATE TABLE countries (
  id            SERIAL PRIMARY KEY,
  slug          TEXT UNIQUE NOT NULL,          -- вечный внутренний ID: 'france', 'kosovo'
  name          VARCHAR(255) NOT NULL,
  class         TEXT NOT NULL CHECK (class IN
                  ('un_member','un_observer','de_facto','territory','special')),
  iso_alpha2    CHAR(2) UNIQUE,                -- NULL у Сомалиленда и пр.
  iso_alpha3    CHAR(3) UNIQUE,
  m49_code      SMALLINT,
  sovereign_id  INTEGER REFERENCES countries(id),  -- для territory: Гренландия → Дания
  valid_period  DATERANGE NOT NULL DEFAULT '(,)',  -- темпоральный крючок, в v1 не используется
  description   TEXT,
  sources       JSONB NOT NULL DEFAULT '[]',
  created_at TIMESTAMPTZ DEFAULT NOW(), updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Базовое покрытие: единица СТРАНОВОГО уровня источника единиц → страна.
-- Внимание (факт dev-БД 2026-07-18): корни дерева единиц — 8 континентов,
-- страновой уровень — их дети (237 шт.); имена там неуникальны (антарктические
-- претензии названы именами стран), поэтому матчинг — геометрический.
-- Политики тут нет — политика живёт в спорах. Единица принадлежит ровно
-- одной записи канона.
CREATE TABLE country_divisions (
  id          SERIAL PRIMARY KEY,
  country_id  INTEGER NOT NULL REFERENCES countries(id) ON DELETE CASCADE,
  division_id INTEGER NOT NULL UNIQUE REFERENCES administrative_divisions(id) ON DELETE CASCADE
);

CREATE TABLE disputed_territories (
  id                 SERIAL PRIMARY KEY,
  slug               TEXT UNIQUE NOT NULL,     -- 'crimea', 'kosovo'
  name               VARCHAR(255) NOT NULL,
  kind               TEXT NOT NULL CHECK (kind IN ('attribution','existence')),
  subject_country_id INTEGER REFERENCES countries(id),  -- existence: чья самостоятельность оспаривается
  is_approximate     BOOLEAN NOT NULL DEFAULT false,    -- границы спора ≠ границы единиц
  description        TEXT,
  sources            JSONB NOT NULL DEFAULT '[]'
);

-- Спор = набор единиц ЛЮБОГО уровня (Крым = 2 единицы 1-го уровня; Косово =
-- его корневая единица). Наполняется сборкой геометрически из NE-полигонов.
CREATE TABLE disputed_territory_members (
  id          SERIAL PRIMARY KEY,
  dispute_id  INTEGER NOT NULL REFERENCES disputed_territories(id) ON DELETE CASCADE,
  division_id INTEGER NOT NULL REFERENCES administrative_divisions(id) ON DELETE CASCADE,
  UNIQUE(dispute_id, division_id)
);

CREATE TABLE disputed_territory_claims (
  id         SERIAL PRIMARY KEY,
  dispute_id INTEGER NOT NULL REFERENCES disputed_territories(id) ON DELETE CASCADE,
  country_id INTEGER NOT NULL REFERENCES countries(id) ON DELETE CASCADE,
  role       TEXT NOT NULL CHECK (role IN ('controls','claims')),
  note       TEXT,
  UNIQUE(dispute_id, country_id)
);

CREATE TABLE disputed_presets (
  id SERIAL PRIMARY KEY, slug TEXT UNIQUE NOT NULL, name VARCHAR(255) NOT NULL,
  description TEXT, is_default BOOLEAN NOT NULL DEFAULT false
);

-- Общая форма выбора (и у пресетов, и у юзеров):
--   counts_as='country'     + country_id (страна-претендент)
--   counts_as='independent'                (только existence-споры)
--   counts_as='not_counted'
CREATE TABLE disputed_preset_choices (
  preset_id  INTEGER NOT NULL REFERENCES disputed_presets(id) ON DELETE CASCADE,
  dispute_id INTEGER NOT NULL REFERENCES disputed_territories(id) ON DELETE CASCADE,
  counts_as  TEXT NOT NULL CHECK (counts_as IN ('country','independent','not_counted')),
  country_id INTEGER REFERENCES countries(id),
  PRIMARY KEY (preset_id, dispute_id)
);

CREATE TABLE user_disputed_preferences (
  user_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  dispute_id INTEGER NOT NULL REFERENCES disputed_territories(id) ON DELETE CASCADE,
  counts_as  TEXT NOT NULL CHECK (counts_as IN ('country','independent','not_counted')),
  country_id INTEGER REFERENCES countries(id),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  PRIMARY KEY (user_id, dispute_id)
);

-- Материализованная карта: КАЖДАЯ единица → (базовая страна, спор-если-внутри).
-- Дети наследуют от своего корневого предка; спорные наборы переопределяют
-- своё поддерево. REFRESH при пересборке канона.
CREATE MATERIALIZED VIEW division_canon_map AS
  ... (division_id, base_country_id, disputed_territory_id NULL);

-- Кэш разрешения локаций экспириенсов (зеркалит experience_location_regions):
-- точка → корневая единица → страна; + геометрическая проверка на спорные
-- наборы.
CREATE TABLE experience_location_countries (
  location_id            INTEGER NOT NULL UNIQUE REFERENCES experience_locations(id) ON DELETE CASCADE,
  country_id             INTEGER NOT NULL REFERENCES countries(id) ON DELETE CASCADE,
  disputed_territory_id  INTEGER REFERENCES disputed_territories(id),
  assigned_at            TIMESTAMPTZ DEFAULT NOW()
);
```

Валидации, которые CHECK не выразит (претендент ∈ claims спора; `independent`
только у existence) — в сборке и в API.

## Семантика разрешения (на чтении)

- `effective_choice(user, спор)` = строка юзера → иначе строка дефолтного
  пресета → иначе `not_counted`.
- `country_of(единица | точка, user)`: если внутри спорного набора — по
  `effective_choice` (`country` → претендент; `independent` →
  `subject_country_id`; `not_counted` → ни к какой стране), иначе — базовая
  страна из `division_canon_map`.
- **Знаменатель «сколько стран»**: записи классов `un_member` + `un_observer`
  без existence-спора — всегда; любая запись с existence-спором (все `de_facto`,
  а также Палестина-observer) — только если юзер разрешил спор как
  `independent` (иначе её территория считается в страну-претендента или
  никуда). `territory`/`special` в счётчик стран не входят — они считаются
  отдельным вторым числом («+ K территорий») из той же выборки.
- Единицы внутри спорных наборов всё равно имеют базовую строку в
  `country_divisions` (инвариант «каждая level-0 принадлежит ровно одной
  записи»; для existence-споров базой служит сама subject-запись, для Крыма —
  Украина), но разрешение для них всегда идёт через `effective_choice`, база в
  подсчёте не участвует. «Каждая level-0» читай как «каждая единица
  странового уровня текущего источника единиц» (в текущем импорте GADM —
  дети восьми континентальных корней).
- **«Страна посещена»** (v1, без миграции отметок): есть visited-локация
  экспириенса, разрешающаяся в неё, ИЛИ есть visited-регион любого вида, чьи
  `region_members`-единицы разрешаются в неё (через `division_canon_map`).
  DISTINCT по странам; префы применяются в момент запроса.
- Смена префа/пресета мгновенно пересчитывает счётчики (это джойн, не
  пересборка данных); UI мягко показывает «под твоей настройкой Косово
  считается отдельной страной».

## Происхождение и сборка: динамический деривиатив из открытых источников

**Требования (2026-07-18):** (1) канон — не наш авторский список и **не
закоммиченный артефакт**: он динамически выводится из открытых источников по
опубликованным правилам; в репозитории живут только правила (код) и два
маленьких конфига исключений. (2) Сборка не привязана к GADM: она оперирует
абстрактным «источником единиц» (`administrative_divisions`; сейчас GADM,
сменяем).

- **Правило членства (публикуется дословно):** запись входит в реестр ⇔
  (а) она есть в ISO 3166-1, ИЛИ (б) она член или наблюдатель ООН, ИЛИ
  (в) она числится государством с ограниченным признанием в Wikidata
  (instance of *state with limited recognition*) на момент сборки.
  Правило (в) приносит Косово, Сомалиленд, Абхазию, Ю. Осетию,
  Приднестровье, Сев. Кипр (Тайвань и Зап. Сахара уже в ISO).
- **Правила классов:** `un_member` / `un_observer` — членство в ООН;
  `de_facto` — правило (в) минус члены/наблюдатели; `territory` — остальные
  записи ISO с флагом independent=no (суверен — из атрибутов источника);
  `special` — записи под международным договором без суверена (фактически
  одна Антарктида). Машиночитаемый носитель — Wikidata (CC0: ISO-коды
  P297/P298, членство в ООН P463, ограниченное признание P31, суверен P17,
  претензии P1336), сверяемый с официальными списками.
- **Споры — тоже не наши:** набор = спорные/breakaway-области **Natural
  Earth** (общественное достояние, курируется их картографическим
  комитетом); претенденты — из атрибутов NE + Wikidata P1336. Ожидаемый
  результат ≈ existence: Косово, Тайвань, Сомалиленд, Абхазия, Ю. Осетия,
  Приднестровье, Сев. Кипр, САДР, Палестина; attribution: Крым, Голаны,
  Кашмир — но состав **фиксируется сборкой, не руками**.
- **Пресеты выводятся, не назначаются:** `de_facto` — из де-факто-владельца
  NE («кто контролирует» — их редакционная политика); `un_widely_recognized`
  — из POV-атрибутов NE / позиций ООН; `strict_neutral` — тривиальное
  правило «всё not_counted». Источник каждого choice — в provenance пресета.
- **Сборка = sync-сервис по существующему паттерну проекта**
  (`syncCanon()` / `getCanonSyncStatus()` / `cancelCanonSync()`), запускается
  админом:
  1. тянет источники (Wikidata SPARQL, членство в ООН, NE-слои admin-0 и
     спорных областей) с кэшем сырых ответов в `data/cache/canon/` —
     незакоммиченный runtime-кэш, как у Wikivoyage-экстрактора;
  2. применяет правила → записи канона; каждая несёт provenance
     «(источник, версия/дата загрузки, правило)» в `sources jsonb`;
  3. апсертит по `slug` (slug'и стабильны между сборками — префы юзеров
     переживают пересборку);
  4. строит crosswalk «единицы странового уровня → страны» **геометрически**:
     единица → NE-полигон admin-0 с максимальным перекрытием → его ISO-код →
     запись канона; имя-матчинг — только fallback (имена на страновом уровне
     неуникальны); остатки — `unit-match-overrides.json`;
  5. приземляет споры на единицы тоже **геометрически**: NE-полигон спора ∩
     единицы источника, опубликованный порог перекрытия →
     `disputed_territory_members`; частичное совпадение → `is_approximate`.
     Никакой завязки на имена/коды конкретного источника единиц;
  6. `REFRESH division_canon_map`; пересчёт `experience_location_countries`;
  7. отчёт: счётчики, неразрешённое, **дифф с предыдущей сборкой** →
     `canon_import_log` (какие источники, какие версии, что изменилось).
- **Ручному оставлено ровно два конфига в репе (правила, не данные):**
  (а) `unit-match-overrides.json` — соответствие корневых единиц текущего
  источника единиц (не членство!); (б) `exceptions.json` — документированные
  отклонения от вывода правил, каждое с обоснованием и ссылкой. Пустой
  exceptions — целевое состояние; непустой — публично объясним.
- **Воспроизводимость и объяснимость — через provenance в БД**, а не через
  закоммиченный снапшот: каждая запись/спор/choice пресета знает, из какого
  источника какой версии и по какому правилу получен; лог сборки хранит
  историю; **дифф между сборками — главный детектор дрейфа источников**
  (страховка от нестабильности Wikidata — урок стратегического ревью;
  подтверждённо плохие значения фиксируются в exceptions).
- **Смена источника единиц** (GADM → geoBoundaries/OSM/…): канон-записи,
  споры, пресеты и префы юзеров **не меняются**; пересобираются только
  crosswalk и приземление споров — теми же геометрическими правилами +
  overrides нового источника. Это и есть цель отделения канона от единиц.
- **Честная неточность v1**: споры приземляются на существующие единицы
  источника; точность = порог перекрытия в правиле. Вырезание
  custom-геометрии — не в v1 (машинерия `custom_geom` в схеме уже есть,
  дверь открыта).
- **Границы сборки**: без AI; сеть — только внутри сборки (админ-операция);
  пользовательский рантайм из сети ничего не тянет.
- **Лицензии**: Wikidata — CC0; Natural Earth — общественное достояние;
  списки ООН — свободны; ISO-коды — через открытые реплики. Источник единиц
  — по своему ADR (сейчас GADM: некоммерческое ограничение известно, канон
  его не углубляет, а изоляция упрощает замену).

## Юзерский слой

- **Карта**: постоянный слой штриховки спорных территорий поверх любого вида.
  Новый Martin-источник (функция над union-геометрией
  `disputed_territory_members`); MapLibre `fill-pattern` — учесть готчу с
  регистрацией паттерна в стиле (см. maplibre-patterns.md).
- **Профиль → «Спорные территории»**: список споров (имя, претенденты, твой
  текущий выбор), переключатель пресета одним кликом, точечный оверрайд
  per-территория. У нового юзера — `de_facto`, явно подписанный.
- **Страница `/countries`**: сводка «Стран: N по твоим настройкам · посещено
  M» + таблица (имя, класс-чип, бейдж спора с твоим выбором, посещённость,
  число экспириенсов), клик → панель страны с её экспириенсами.
- **Методология «Откуда этот список»**: блок/страница на `/countries` с
  дословным правилом членства, списком источников (версии и даты загрузки из
  лога сборки, лицензии) и содержимым exceptions (если непустой); карточка
  записи показывает её provenance («в списке, потому что: ISO 3166-1; член
  ООН — по данным сборки от 2026-07-18»), карточка спора — источник
  («Natural Earth disputed areas, v5.x»). Это продуктовая фича
  нейтральности, не только техдокументация.

## Админ-слой

Страница в `/admin/*`: список канона с фильтрами по классам, карточка спора,
покрытие/споры на мини-карте, кнопка «пересобрать канон из источников» с
прогрессом (sync-статус) и отчётом/диффом последней сборки. Правка данных —
только через правила/exceptions в коде (v1), не формами.

## Безопасность

- **Префы по спорным территориям — чувствительные данные** (фактически
  политические взгляды; рядом GDPR ст. 9): приватные по умолчанию, отдаются
  только владельцу (`requireAuth` + ownership-проверка), в логи не пишутся,
  наружу (публичные профили, будущие лидерборды, любые агрегаты) не светятся
  никогда без явного отдельного решения.
- Все новые write-эндпоинты — параметризованные запросы через Drizzle, вход
  валидируется (slug'и, enum'ы choices, претендент ∈ claims).
- При реализации: обновить `docs/security/SECURITY.md` (новая поверхность,
  классификация данных префов) и `asvs-checklist.yaml`.

## Открытые вопросы

- Оккупированные с 2022 области Украины: линии контроля не ложатся на единицы
  и текучи — в v1 спорами не моделируются; вернуться при появлении механики
  вырезания или явного запроса.
- «Спящие» претензии со стабильным контролем (Фолкленды, Гибралтар): состав
  теперь определяет NE-слой споров; если вывод правила расходится с
  travel-честностью (штриховать Фолкленды наравне с Крымом — сомнительно) —
  разруливаем через `exceptions.json` с обоснованием.
- Где `/countries` живёт в навигации (отдельный пункт vs вкладка Discover).
- Финальный состав пресетов (`de_facto`, `un_widely_recognized`,
  `strict_neutral` — достаточно ли трёх) и точные правила их вывода из
  атрибутов NE/ООН — уточнить на фактических данных сборки.
- Свободная ассоциация (Острова Кука, Ниуэ): что даёт правило членства
  (в ISO есть, в ООН нет, ограниченное признание — нет) → класс `territory`;
  если это неверно travel-идентичности — кандидат №1 в `exceptions.json`.
- Проверить фактический состав NE disputed/breakaway слоя против ожидаемого
  набора споров (сборка покажет; расхождения — через exceptions с
  обоснованием).
- Каденция пересборки канона (по релизам источников / по кнопке / по
  расписанию) и политика применения диффа (авто vs подтверждение админом).
- Пороги геометрического матчинга (crosswalk корневых единиц и приземление
  споров) и качество fallback-матчинга по именам — калибруем по фактическому
  отчёту сборки.
- **Черновик правила вырезки для carve-среза (выведен из живой диагностики
  2026-07-19, проверен на всех 94 спорах):** NE-полигоны генерализованы, и
  ST_Intersection с детальными юнитами рождает sliver-шум выравнивания
  (украинские кромки у Приднестровья, сочинские у Абхазии). Идемпотентное
  лечение — три опубликованных порога: «in»-кусок отбрасывается как шум ⇔
  (доля от спора < 1%) ∧ (доля от юнита < 50%) ∧ (площадь < 0.08°²); юнит
  снэпится в «полностью спорный» (остаток отбрасывается) ⇔ остаток < 10%
  юнита ∧ < 0.08°². Каждый порог страхует свой класс: %-от-спора защищает
  куски маленьких споров (Байконур 83/17 не тронут), %-от-юнита — целиком
  проглоченные микроюниты (Кашмир), абсолютный — крупные земли. Проверка:
  Приднестровье → только Молдова, Сомалиленд → целые юниты, Крым — херсонские
  клочки ушли, легитимные разрезы целы.
- **Кросс-сверка геометрии споров вторым источником (2026-07-19):** OSM-границы
  по wikidata-тегу (44 из 85 нашлись), land-clipped IoU против NE: 25 согласны
  (≥0.7 — Косово, Абхазия, Ю. Осетия, Тайвань, Голаны, Газа, Фолкленды…),
  10 расходятся — морские атоллы (OSM включает акваторию/рифы) и **Байконур:
  NE-полигон в ~170 раз больше реальной арендной зоны OSM (IoU 0.006) — NE
  для него непригоден**. Механика сверки — кандидат в постоянный
  quality-гейт carve-среза; замена геометрии Байконура — OSM (ODbL-оговорка
  при доставке в прод) или ручной полигон по договору аренды.
- **Правило carve v4 — LIST-FIRST (РЕАЛИЗОВАНО в демо-пайплайне 2026-07-19,
  все 94 спора перепроверены автоматом; требование Николая: механика не должна
  зависеть от точности геометрии — состав определяет публичный список, где он
  есть):**
  (0) **Списки состава** per dispute: Wikidata **P150-состав + обратный P131**
  («расположено в», фильтр admin-единиц P31/P279*→Q56061), оба на 2 уровня
  вглубь, **+ subarea-члены OSM-реляций** (резолв через P402); матчинг в
  листовые юниты GADM координатами **P625 point-in-unit** (имена/транслит не
  нужны); провенанс источников хранится на юните. Покрытие: списки у 36 споров,
  248 юнитов, 1881 точка.
  (1) **Режим спора:** `list` — список воспроизводит зону (покрытие ≥90% и
  избыток ≤15%): состав = юниты списка ЦЕЛИКОМ, геометрия НЕ режет и НЕ
  добавляет — существенные гео-находки уходят во флаг `disc_geo`
  (кросс-чек); `hybrid` — список есть, но линия де-факто режет юниты: юнит
  списка целиком при ≥90% внутри или абс. остатке <0.02°² (без share-пола —
  захватывает Bender и ПМР-сёла западного берега), прочие режутся геометрией;
  `geom` — списка нет/не лёг: чистая геометрия (гео-промоушен ≥98%,
  снэп-фильтр). Guards списка: share ≥0.35 в list-режиме (иначе флаг
  `disc_list` «в списке, но вне зоны»), юнит ≤1.2×max(зоны, 0.5°²), bbox+1.5°.
  (2) Исчерпывающая композиция (hybrid/geom): полные юниты ≥90% зоны → остаток
  = шум выравнивания; существенный кусок (≥25% юнита или ≥0.02°²) режется
  всегда (кейс Zvečan).
  (3) **Источник зоны:** точная линия OSM (land-clipped) при land-clipped
  IoU ≥0.6 с NE (29 из 94), иначе NE 1:10m (деривация+fallback); Байконур —
  принудительно OSM.
  (3b) **Островной снэп (визуальный QA, кейс Курил — NE-линия резала Итуруп
  поперёк суши):** при резке юнит раскладывается на компоненты суши
  (ST_Dump); компонент ≥85% внутри зоны идёт целиком — граница претензии
  проходит проливом, а не линией поперёк острова. Снэп только ВВЕРХ:
  симметричный нижний порог отвергнут калибровкой (съедал реальные карманы
  линии — Переви/Трусо у ЮО). Побочно: крымские кромки-тёзки поглощены
  (suspects 26→0), Кипр оказался list-exact (в GADM есть северная сетка
  ТРСК — 5 юнитов целиком, exh). QA-проход: 24 скрина + программный детектор
  (mid-island cuts/шум/перегруз) — резок поперёк островов не осталось;
  «тёмный Аксай-Чин» в J&K — не баг, а клейм-слой (OSM-претензия княжества
  шире NE-зоны; Аксай-Чин заодно отдельный спор) — легенда уточнена
  («де-факто у страны юнита»).
  (3b-2) **Зона из претензионных районов + ribbon-критерий (кейс ПМР,
  подтверждён измерением):** разница «юнит GADM − зона NE» у ПМР = 22.4%
  площади, но это лента шириной ~1.3 км вдоль ВСЕГО периметра — профиль
  генерализации NE 1:10m, а не линия контроля (и даже против точного OSM
  сам GADM даёт ленту ~1 км). Правила: (а) если своей OSM-реляции у спора
  нет, но объединение OSM-границ претензионных районов воспроизводит
  NE-зону (покрытие ≥0.7, избыток ≤0.25) — зона := это объединение
  (`osm-claim`, доверие B; Джамму отвергнут по избытку — претензия-княжество
  шире зоны, ЛНР/ДНР по покрытию — реляции неполные); (б) ribbon-критерий в
  гибриде: списочный юнит целиком, когда share ≥0.7 и (площадь разницы)/
  (периметр юнита) < 0.018° (~2 км средней ширины) — «разница есть лента
  точности, а не граница». Итог ПМР: {юнит Приднестровье целиком, Бендер
  целиком}, резки нет, exh. **Лента-зачистка по всем 94 (обобщение):**
  (а) лента-поглощение — ЛЮБОЙ резаный юнит (не только списочный) идёт
  целиком при ≥70% в зоне и остатке-ленте тоньше ~2 км средней ширины
  (площадь/полупериметр < 0.018°); (б) лента-сброс — вторжение зоны ≤25%
  юнита, тонкое (<0.012°) и вытянутое (изопериметрика >10) — шум совмещения,
  в мусор-лист; guard: споры с лентообразной по природе зоной (ширина
  <0.06°: корейская ДМЗ, Шебаа, дунайские острова, Латрун) из сброса
  исключены — их куски легитимно лентообразны. Итог прогона: 18 споров,
  42 юнита поглощены (Крым: 6 прибрежных раионов-тёзок 89–98% — бывшие
  suspects — целиком, осталась лишь реальная резка Арабатской стрелки;
  Звечан 96%; Джунагадх 22→12 резок; Сабах ×5; ДМЗ-мёны в полосе;
  гималайские юниты у грубых NE-линий), 4 тонких вторжения сброшены.
  (3b-3) **Подмена объекта зоны (кейс Аруначала, подтверждён измерением):**
  OSM-реляция, найденная по QID спора, может оказаться ДРУГИМ объектом:
  QID «Аруначал-Прадеш» = индийский ШТАТ (7.63°²), а NE рисует китайскую
  ПРЕТЕНЗИЮ «Южный Тибет» (6.24°²), которая заканчивается у перевала Дифу и
  не включает юго-восточные районы (Тирап/Чангланг/Лонгдинг — блоб
  ~16 500 км², ширина 27 км — не лента); IoU 77% прошёл порог 0.6, и зона
  молча стала штатом (перезаклад спора). IoU-гейт не ловит семантическую
  подмену — сеть здесь экспертная ревизия: механизм `zone:'ne'` в
  expert-review.json снимает свитч; итог — зона=претензия, 14 районов
  целиком (было 22), штатные районы вне претензии помечены `disc_list`;
  Китай добавлен претендентом (в автоданных отсутствовал).

## Инкремент (2026-07-20): правило kind + hi-res суша демо

**Правило `kind` реестра споров (зафиксировано после бага Абхазии).**
`kind='existence'` ⟺ предмет спора — государственность: контролирующая
сторона — живое де-факто государство канона (`countries.class='de_facto'`),
либо спор о признании государства (Израиль). Тогда `subject_country_id`
обязателен и указывает на это государство. Всё остальное — `attribution`.

Найденные и исправленные ошибки данных (демо-БД, при порте в canonSync —
перенести в exceptions/seed):
- **abkhazia** — роли были перепутаны (`ge:controls / republic-of-abkhazia:claims`);
  из-за этого kind остался attribution и subject был пуст. Исправлено зеркально
  Южной Осетии: `ge:claims / republic-of-abkhazia:controls`, kind=existence,
  subject=republic-of-abkhazia.
- **taiwan** — контролирует `tw` (class=de_facto), но kind был attribution →
  existence, subject=tw.
- **israel** — спор о признании члена ООН → existence, subject=il.
- **artsakh** остаётся attribution: субъект распущен (P576), «спор существования»
  закрыт; статус «исторический» живёт в ярусах. **w-sahara** остаётся attribution:
  субъект САДР в каноне class=territory, и спор — реальный территориальный раздел.

`disputes.json` демо теперь генерится скриптом `gen-disputes.mjs` из БД
(с семантическим диффом против прежней версии) — файл больше не ad-hoc.

**Суша глобального мока**: NE 1:50m admin0 (public domain), без симплифая,
относительные SVG-пути точностью 3 знака (`ST_AsSVG(geom,1,3)`) →
`countries_svg_hi.json` (~1.2MB). Этого хватает до зумов узлов (~0.01°/px);
детальнее не нужно — юниты споров и так GADM.

## Инкремент (2026-07-20b): архив реестра — первоклассный статус

Записи реестра с жизненным статусом «разрешён / исторический / передан /
не-спор / дубль / субъект распущен» (Арцах, ДНР/ЛНР, остров Ганса, Тиран и
Санафир, гора Скопус, обе полосы корейской ДМЗ, обе «ничейные земли» 1949–67,
дубль Илеми) — это **архив**, а не живые споры. Правила:
- в продукт архив не выносится вовсе: ни зоной, ни флажком, ни бейджем;
- в ревью-хабе архив показывается отдельной приглушённой группой в конце
  списка и серым на мировой карте — только для полноты реестра;
- машиночитаемо: `tiers.json` несёт `archived: bool` + `status: text`
  (генератор ярусов), потребители фильтруют по полю, не по регэкспу текста;
- при порте в canonSync: статус жизненного цикла должен стать колонкой
  реестра (`status` / `resolved_at`), а не свойством ярусов.

## Инкремент (2026-07-20c): охота за источниками для слабых зон

**Правило**: зона с доверием C/D в чисто геометрическом режиме обязана пройти
охоту за лучшими источниками по трём контурам, прежде чем считаться финальной:
1. **Автоматический** — OSM (реляции/пути boundary=disputed|claim глобальным
   запросом + Nominatim по имени в области спора) и Викидата (P402/P3896/P625).
   Кандидаты показываются в ревью; в зону принимаются только экспертной правкой
   (`zone: <osm-rel-id>` в экспертном слое) после визуальной сверки.
2. **Каталог профильных ресурсов** (курируемый, `spec_sources.json`): сервисы
   ООН и сообществ по конкретным конфликтам, с пометками машиночитаемости,
   лицензии и назначения (замена зоны / линзы / сверка / справка). Ключевое:
   УКГВ ООН oPt на HDX (зоны Осло A/B/C, барьер, В. Иерусалим — кандидат замены
   D-зоны), COD-AB Юж. Судана (Абьей отдельным юнитом по PCA 2009), geoBoundaries
   CC-BY (границы «как страна видит себя» — готовые взгляды сторон для линз),
   LSIB Госдепа (public domain, статусы линий), UN Clear Map (сверка, лицензия
   ограничена), DeepStateMap + GeoJSON-зеркало (линия фронта Украины — только
   справка, счёт активной войны не моделируем). Отрицательные результаты тоже
   фиксируются: открытого датасета LAC не существует — OSM там лучший источник.
3. **Ручной** — карты МИД/ООН/научные атласы, оцифровка (UNDOF/UNIFIL — PDF).

**Кейс-образец Бара-Хоти**: NE-блоб (D) заменён OSM-реляцией 2713484 «Barahoti
disputed area» (~820 км², пять урочищ среднего сектора); линии позиций сторон
(9575754 КНР / 13559375 Индия) незамкнуты — зона и есть площадь между ними.
Механизм: `gen-alt-zones.mjs` качает реляции из экспертных правок, пайплайн
вливает их в общий OSM-поток (клип по суше, NE — в синий пунктир сверки).
Итог прогона охоты: у 21 из 58 слабых живых споров есть OSM-кандидаты
(среди них: Extent of UAE Claim at Abu Musa — rel 9520136, Paracel Islands —
rel 17296617, линии претензий Бутана и «Bhutan border in LSIB»).

**Готча Overpass**: перегруженный сервер возвращает валидный JSON с
`remark: runtime error` и пустым `elements` — это НЕ успех, и такой ответ
нельзя кэшировать; батч-запросы с name-regex по крупным bbox убивают сервер —
глобальный запрос по редкому тегу + Nominatim по именам дешевле и надёжнее.

## Инкремент (2026-07-21): узлы споров — разбиение, а не стопка

Реестр хранит пересекающиеся записи узла осознанно (зонтичный спор «всё
княжество Джамму и Кашмир» + споры-куски по зонам администрирования), но
**продукт обязан показывать узел разбиением без пересечений**:
- правило: пересечения зон разрешаются приоритетом более специфичной
  (меньшей) зоны; зонтик получает остаток; каждая точка узла принадлежит
  ровно одной зоне;
- каждая зона разбиения — обычный регион в дереве тревел-направлений своего
  фактического администратора, помеченный ⚠ спорным (Пакистан → Азад Кашмир,
  Гилгит-Балтистан; Индия → Дж&К, Ладакх; Китай → Аксай-Чин, Шаксгам);
- зонтичный спор в дерево направлений не попадает — он живёт справкой узла
  (иначе двойное покрытие);
- засчёт: регион у чек-ина стабилен при любой линзе (Скарду → «Гилгит-
  Балтистан» всегда); линза меняет только страновую атрибуцию в профиле;
- при порте: членство узла (какие споры составляют узел) — данными
  (dispute_node таблица или parent_dispute_id), партиция считается в PostGIS
  тем же правилом; демо-реализация — gen-node-partition.mjs.

## Инкремент (2026-07-25): канон — не только страны

**Находка:** класс `special` в `countries` уже существует и содержит ровно
одну запись — `aq` (Антарктида). Слот был, принцип сформулирован не был.

**Принцип:** хребет канона — множество **счётных сущностей**, среди которых
страны лишь самый крупный класс. Требований к записи два: (1) у неё есть
экстент; (2) она либо лист, либо имеет собственное L3. Остальное — классы.

### Вне стран, но посещаемо

**Антарктида.** Порядка ста тысяч туристов в год, подавляющее большинство —
Антарктический полуостров. Договор об Антарктике заморозил претензии семи
стран, Земля Мэри Бэрд не заявлена никем. В каноне уже есть (`aq`,
`special`).

Это же — наглядный кейс выбора источника L3: одна территория, два
несовместимых деления прямо в наших данных.

- GADM: `Antarctica` → France · Australia · Norway · United Kingdom ·
  Antarctica — **по секторам претензий**;
- Wikivoyage (wv=2): Антарктический полуостров · Восточная · Западная ·
  море Росса · Южный полюс · острова Южного океана — **по-туристски**.

**Решение: L3 Антарктиды — туристический, не секторный.** Никто не считает
себя посетившим «Австралийскую антарктическую территорию». Первый случай,
когда L3 приходит не из административного источника — источник L3 есть
продуктовое решение, а не техническое.

**Terra nullius — земля без претендентов.** Бир-Тавиль (~2060 км² между
Египтом и Суданом; не заявлен никем, поскольку претензия означала бы отказ
от Халаибского треугольника; экспедиции туда ездят), Земля Мэри Бэрд,
Гронья Сига на Дунае (не заявлена ни Хорватией, ни Сербией — обратная
сторона того же спора; там сидит «Либерленд»). В дереве единиц нет ничего
из перечисленного. **Решение: отдельный класс канона**; геометрия простая
(Бир-Тавиль — четырёхугольник по параллелям).

**Особые режимы доступа — метка на узле, а не запись канона.** Уже есть в
дереве: `Athos` под Грецией (автономное монашеское государство,
диамонитирион, только мужчины), `Svalbard and Jan Mayen` → `Svalbard`
(норвежский суверенитет, но безвизовый режим по трактату, порядка 70 тыс.
посетителей в год), `Brčko` (кондоминиум внутри Боснии). Уже в реестре
споров: обе корейские DMZ (помечены «не спор: полоса перемирия»), при этом
JSA — массовое туристическое место. Сюда же буферная зона ООН на Кипре и
UNDOF на Голанах.

Экзотика, очерчивающая границы модели: Фазаний остров (франко-испанский
кондоминиум со сменой суверенитета каждые полгода), Мальтийский орден
(суверенный субъект международного права без территории, экстерриториальные
владения в Риме).

**Не география, а правило счёта:** транзитные зоны аэропортов и
международные воды. Конвенции счётных сообществ здесь расходятся (TCC
засчитывает даже краткую посадку, более строгие списки требуют
фактического въезда), так что правило «что считается визитом» продукту
придётся определить своё — независимо от канона.

### Следствие, которое важнее спорной механики

Метки режима доступа («нужен пермит», «безвизово по трактату», «зона ООН»,
«доступ закрыт») дают путешественнику **практическую** пользу при
планировании — в отличие от большинства спорных пометок, остающихся
справочными. Афон, Шпицберген, JSA, закрытые погранзоны: вопрос «как туда
попасть» важнее вопроса «чьё это».

**При порте:** расширение enum `countries.class` (`terra_nullius` рядом со
`special`) и поле режима доступа **на узле дерева**, а не на записи канона —
режим относится к территории, а не к суверенитету.

## Инкремент (2026-07-26): пересмотр модели — полный разбор вынесен отдельно

Сессия 25–26 июля пересмотрела несущие допущения этого документа. Полная
фактура, числа и обоснования — в
[canon-model-rethink-2026-07-26.md](canon-model-rethink-2026-07-26.md).
Здесь — только то, что меняет положения самой спеки.

**Отменяется как основной путь:** carve-пайплайн, зоны как самостоятельная
геометрия, SQL-разбиение узлов (инкремент 2026-07-21), ручные ярусы и
уровни доверия как машинерия (инкременты 2026-07-20b/c, 2026-07-23), охота
за границами через Overpass. Ось курьёзов и архив **остаются** — но как
критерии отсечения, а не как приговоры в таблице.

**Заменяется вычисляемым предикатом:** спор счётен тогда и только тогда,
когда его территория равна объединению **целых** узлов дерева. Классы 1/2/3
выпадают сами и пересчитываются при смене источника подложки; 94 ручных
вердикта становятся кэшем вычисления.

**Порядок сборки** (замена прежнему «канон внутрь импортированного
дерева»): канон независимо → L1 → L3 по одной стране; точность спора
решается в момент L3 этой страны. Страна — **явная пометка на узле**, не
глубина (во вью Викитревела на втором уровне макрорегионы и страны
вперемешку). L1 — отображение «страна → группа», а не дерево. Линза
действует на подложке (`country_divisions`), а не на дереве.

**`kind` — граница работ:** 8 споров `existence` решаются на каноне (у всех
обе стороны уже есть записями), 86 `attribution` — на подложке или в L3.

**Подложка подключаемая по странам.** GADM не универсален: Южной Осетии в
нём нет, кашмирские единицы несут претензии в названиях, глубина неровная,
лицензия некоммерческая. COD-AB (HDX/OCHA, обычно CC BY-IGO) по Грузии даёт
Абхазию и Южную Осетию отдельными ADM1 — класс 2 становится классом 1 без
всякой геометрии. **Правило:** подложку меняем по странам, но спорный узел
берём из одного источника целиком.

**Архив → временная валидность.** Булев `archived` неверен: BIOT показал,
что это процесс со стадиями (договор подписан 05.2025, в силу не вступил).
`countries.valid_period` уже есть в схеме и не используется (0 из 277) —
спорам нужен такой же период. Отсюда открытый вопрос: атрибуция визита по
канону **на дату визита** (СССР, Чехословакия, Нидерландские Антилы…).

**Счётность — тег на узле, а не класс в каноне.** Линия «что считается
отдельным» проведена по ISO, а ISO не про путешествия (Буве в каноне,
Канары нет; Занзибар со своим штампом нет). Вместо переноса линии —
стандарты как пресеты (ООН / ISO / TCC ~330 / NomadMania ~1300) поверх
дерева, которое тоньше любого из них. Механизм пресетов уже написан для
споров. Счётность спора — тот же тег.
