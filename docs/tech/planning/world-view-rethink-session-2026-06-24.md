# World View — журнал сессии: решения по ревью + продуктовая картина (на память)

> Статус: рабочая память брейншторма, 2026-06-24. НЕ коммит, не финальная спека. Фиксирует и конкретные решения по ревью (Точки 1–20), и крупный продуктовый разворот, к которому мы пришли в конце. Где решение не зафиксировано формально — помечено. Сопутствующие доки: `world-view-workflow-rethink.md` (модель/авторинг, теперь это back-office), `world-view-workflow-rethink-review.md` (трёхлинзовое ревью).

## Часть 1 — С чего начали

Шли по пунктам трёхлинзового ревью документа про переосмысление workflow (как строить мир и как пользователь его отмечает). Разбирали каждый блокер и важный пункт по очереди, для каждого — варианты, продуманные ПМ/юзером/инженером, и выбор. Получилось 20 «Точек». Ближе к концу обсуждение переросло из «как чинить модель» в «а что вообще за продукт мы строим», и это сместило приоритеты — см. Части 5–9.

## Часть 2 — 20 решений по ревью (журнал)

1. **Фазировка — C:** строим полный Шаг 0 (весь фундамент), а не урезанный MVP.
2. **Sign-off — C (гибрид по перспективе):** «де-факто» включается, как только закрыты её пробелы; остальные политики и дорогие споры дозакрываются позже. Утверждение — веха качества, не вход; пользоваться можно и до.
3. **Членство канона — A (курируемый):** ISO 3166 как старт + правило «отдельная travel-идентичность» + ручные де-факто-добавления (Косово, Сомалиленд). Внутренние единицы (Шотландия, Аланды) — субнац, не канон. TCC/NomadMania — только как референс.
4. **Подсчёт спорных — A:** визит в спорную часть засчитывает страну-владельца под текущей политикой (как любой кусок). Отметки физические (против единиц), при смене линзы не теряются; счётчики — производные.
5. **Транс-страна без назначения частей — A:** страна засчитана, надгруппы показаны «уточняется» (не угадываем); односоставным надгруппа засчитывается сразу.
6. **Карта при политике — A (нейтральная):** рендерим единицы, спорное всегда заштриховано; политика меняет только числа/подписи, не заливку. Тайлы остаются перспективо-агностичными.
7. **Канон vs существующее — A (новое рядом):** новый стек строится параллельно, старое работает, ретайр потом; миграция = однократный экспорт, а не операция на лету.
8. **Деление страны + носитель part→надгруппа — C:** несколько именованных общих схем деления на страну (8 округов / 85 субъектов); привязка частей к надгруппам — на паре (иерархия × схема).
9. **Геометрия споров — B (вырезание в v1):** внешний источник + `ST_Difference` + версии. Полная возможность сразу.
10. **Источник геометрии — B (OSM разрешён):** принимаем ODbL share-alike + пермиссивные (Natural Earth, Wikidata). Для будущего публичного продукта обязательство share-alike + атрибуцию учесть отдельно.
11. **Global gap — B (по всем листьям):** полная геометрическая полнота; «ничьи» (Антарктида, нейтральные воды) закрываются спец-владельцем «не страна».
12. **Перекрытия — A (три механизма):** дерево («где X») / виды (взаимоисключающие схемы) / groupings (культурно-исторические перекрытия бейджами внутри вида).
13. **Straddling-части (Стамбул) — гибрид по экспириенсам (free-text юзера):** straddling-часть остаётся в обеих надгруппах; кредит юзеру резолвится по координатам отмеченных им экспириенсов (point-in-region) + ручная отметка, если был в другой части без экспириенса. Казахстан-тип режется по-настоящему. Нет сигнала → «уточняется». Обобщение: координаты экспириенсов — общий разрешитель «в какой части я был» (улучшает и Точку 5).
14. **Мульти-споры (Спратли/Кашмир) — A:** дробим на под-объекты по фактическому контролю сразу; де-факто-владелец на сектор; experience-координаты резолвят.
15. **Governance канона — C (версионируемый со снапшотами + откаты):** + отметки на единицах всё равно переживают переименование/слияние/распад; admin-курируется.
16. **Авто-матчинг импортёра — A:** уверенный авто-матч; неоднозначное → явный пробел для ручного разрешения; переиспользуем существующий match-review.
17. **Флоу в доке — A:** переписать сценарии как отдельные пошаговые флоу (A1–A12 автор / B1–B6 путешественник) с «что видишь/куда жмёшь»; концептуальные разделы остаются нарративом. (Уже внесено в `world-view-workflow-rethink.md`.)
18. **Иерархии × эпохи — A:** темпоральная валидность на членстве (одна иерархия резолвится под эпоху, СССР→15) + эра-скоуп иерархии для структурно-эпохальных схем (блоки Холодной войны). НЕ форк-на-эпоху.

**Зафиксировано не до конца:**
- **Точка 19 (один канон с эпохами vs канон-на-эпоху):** концептуально склонились к **A — один темпоральный реестр** (все сущности + интервалы существования + граф преемственности supersedes/superseded_by; эпоха = срез; полнота только для настоящего, история best-effort; история курируется до «узнаваемых сущностей», не весь атлас). Разобрали и переходы (развал/поглощение/слияние = плотность succession-событий; transition-completeness = разложить территорию предшественника по преемникам; сдвиги границ — вырезаемой геометрией; преемственность бывает перспективо-зависимой — Югославия). Формальный выбор не зафиксирован — ушли в продуктовую переоценку.
- **Точка 20 (на чём держать свойства — якоря):** переросла в таксономию (см. Часть 4). Концепт: география → на земле, коалиции → на стране, и плюс выявились якорь «население» и «перцептивная/культурная перспектива». Не финализировано формальным выбором.

## Часть 3 — Третья ось: время (эпохи)

Время — третья линза наряду с политикой: полная линза = **эпоха × политика × композиция**. Инвариант «отметил один раз — линза пересчитала» работает и по времени: отметка против единицы + дата визита под 1989 засчитывает СССР, под 2025 — нынешнюю страну тех же мест. Уже предвосхищено в groupings (`joined_date`/`left_date`).

Механика: интервалы существования у канон-стран; темпоральная валидность членств в иерархиях; эра-скоуп иерархии; покрытие исторической страны = объединение нынешних единиц преемников (СССР = 15 республик), вырезание — только где границы разошлись; визит с датой → эпоха автоматом + ручная линза. «Версия» (история правок, Точка 15) ≠ «эпоха» (историческое состояние).

Скоуп — задаток: в v1 только крючки (интервалы, темпоральная валидность, дата визита), сама фича «эпохи» — поздняя фаза. (Внесено в `world-view-workflow-rethink.md`, раздел «Время — третья ось».)

## Часть 4 — Что чьё свойство: якоря и грани

Ключ: у разных свойств разный **якорь**, и их больше, чем «земля/страна».

- **Физгеография / экология** (континент, Сахель) — свойство **земли**, объективно-стабильно. Силезия ∈ Европа всегда.
- **Принадлежность стране** (Силезия: Германия→Польша; Крым: UA/RU) — связь **земля↔страна**, ×время×политика.
- **Политические коалиции / страновые наборы** (ЕС, НАТО, Антанта, СССР-как-союз) — свойство **страны** (целиком, декларативно), земля наследует транзитивно; ×время, иногда ×политика. «Силезия в Антанте» — только через свою страну.
- **Этнокультурные родины** (Курдистан, Сапми, Каталонские земли) — свойство **населения** (народ-на-земле); экстент = куски, критерий = где живёт самоопределяющийся народ; нечётко, через границы, ×культурная-перспектива.
- **Перцептивные / ментальные карты** (Центральная vs Восточная Европа, Запад, Глобальный Юг) — **нет фиксированного якоря**, резолвятся **культурной перспективой**; самоидентификация — одна из перспектив.
- Также: лингвистические (организация = страна; ареал = население), религиозные (адепты = население / госрелигия = страна), историко-политические (страна ×время), экономико-девелопментные (страна ×время), цивилизационные (страна/население + перцепция), туристические списки (= вид/композиция).

**Распилённая структура любой надгруппы:** (экстент: piece-level vs country-level) × (критерий: гео/эко/политика/экономика/этнос/язык/религия/перцепция/история) × (оси резолва: время, политическая перспектива, культурная перспектива).

**Единый примитив «грань» (facet):** именованная система регионов по одному критерию, со своей формой (дерево/плоская), якорем, линзами и полнотой (гейтится vs частичная по природе). Тогда: «надстрановая иерархия» = грань-дерево; «groupings» = плоская грань; «канон стран» = привилегированная страна-грань (единица счёта); перспективы/эпохи = линзы. **Атлас = библиотека граней; движок один и общий; богатство = данные, а не код.**

## Часть 5 — Продуктовый разворот (как ПМ)

Главное осознание: мы проектировали **авторинг идеального мира**, а работа пользователя — **трекать на уже готовом мире**. Богатая модель (перспективы/эпохи/споры/грани) — это back-office + опциональные power-фичи, не онбординг. Мир должен приезжать **готовым** (засиженный из открытых данных), пользователь его не строит. Полнота/sign-off служат данным, а не путешественнику. Риск: строить собор раньше хижины, и взаимное раззадоривание на красивой модели.

Что хочет путешественник (JTBD): закрасить карту, видеть рост числа/следа, видеть что осталось, планировать. Память/артефакт — бонус. «Понять место во всех гранях» — вторично (это Атлас).

## Часть 6 — NomadMania: что забрать, что починить

Пользователь был активным юзером NomadMania, ушёл по политическим мотивам: владелец принимал предвзятые личные решения (говорил «слишком много русских», банил всех с паспортом РФ на офлайн-мероприятиях). Любил: саму карту, идею мастер-списка, видимый прогресс путешествий, планирование, и **соревнование** (лез вверх в когортном рейтинге — например, среди паспортов РФ до #30).

Расцепление: **единый общий список** (хорошо — даёт сравнение) vs **единый предвзятый владелец, рулящий им и исключающий людей** (плохо). Берём сравнимый субстрат, чиним управление (нейтральное/сорсед/версионируемое) и участие (инклюзивное, без банов по паспорту).

## Часть 7 — Эмоциональное ядро и итоговый синтез

Уточнялось в несколько шагов: сперва казалось, что нужен форсированный единый мастер-список; потом — что рейтинг был приватным личным прогрессом; в итоге — **соревнование ценно, но матч-ап выбирает сам пользователь**: на какой сетке/грани и против какой когорты мериться. «Русские до 30 по ЮНЕСКО» = (когорта) × (грань). Личный прогресс, но в выбранном тобой сравнении.

**«Единый мастер-список» растворяется как требование.** Нужен не один список, а **сравнимое начисление на общих сетках, нарезаемое любым срезом (грань × когорта) на лету.** NomadMania = одна сетка × фильтр по нации; мы = N сеток/граней × любая когорта, и матч-ап выбираешь ты. Лидерборд — это запрос «ранжируй когорту C по сетке G».

**Итоговая суть продукта:** персональный комплишн-трекер на общих каноничных сетках, где пользователь выбирает и что закрывать, и с кем мериться. Нейтральный, инклюзивный, много сеток вместо одной.

**Дифференциация vs NomadMania:** много сеток (а не одна) + нейтральное управление + инклюзивные когорты (все равны) + матч-ап выбираешь ты, а не владелец.

## Часть 8 — Роли (кто что делает)

**Админ** строит одну каноничную **настраиваемую** структуру и задаёт **дефолтный вид** (это и есть курирование единого списка — но прозрачное, версионируемое). **Пользователь** только тыкает галочки: выбирает вид (перспектива / гранулярность / какие грани) и матч-ап для соревнования. Пользователь иерархию НЕ строит.

Дефолтный вид = общая сетка, на которой сидит толпа (плотный лидерборд); кому не нравится — переключает вид (нейтральность-эскейп) и меряется внутри когорты этого вида. Один механизм (настраиваемые виды) — две роли: дефолт = общее поле; кастом = личное/нишевое.

## Часть 9 — Скоуп: ядро v1 vs позже

**Ядро v1:** засиженный готовый мир (канон + континенты) + личная петля «крась / прогресс / что осталось» + планирование, на дефолтном своде, который можно перенастроить/расширить.

**Заложить с первого дня (дешёвая страховка, саму фичу не строим), чтобы всё «легло»:**
- отметки против административных единиц (субстрат для любой сетки, для перспектив/эпох/граней);
- свод как «грань №1» (география), а не спец-случай;
- нейтральный сорсед/версионируемый канон;
- опциональные атрибуты профиля (паспорт/нация, возраст, друзья) для будущих когорт;
- темпоральные крючки (интервалы существования, дата визита).

**Позже / fast-follow:** когортные лидерборды (грань × когорта); новые грани-коллекции (ЮНЕСКО — а experiences у нас уже есть! — язык, религия, этнокультура, перцепция); UI переключения перспектив; эпохи/история; вырезание геометрии споров; AI.

**AI — припарковано («потом подумаем»):** AI строит мир (back-office: канон/иерархии/споры/грани со ссылками); AI восстанавливает след юзера из цифрового следа (Google Timeline / фото / брони / текст) — убивает онбординг; AI — нейтральный сорсед-объяснитель споров (анти-bias клин); AI-планировщик комплишна; AI генерит коллекции по запросу. Делает амбициозную модель выполнимой (каменщик — AI), но обсуждаем позже.
