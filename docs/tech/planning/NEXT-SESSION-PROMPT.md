## Проверка спеки уже сделана — не повторяй её

5 августа 2026 спека была независимо проверена по коду и по живой базе, и в исходном виде не
устояла. Результат проверки записан комментарием в **#500**, а что именно изменилось и почему —
в § 11 спеки. Оттуда же родились issues #502–#506.

Что было решено по итогам (не перерешивай без причины):

- гейт держит **весь объект** — контент, точки и экспонаты одним предложением, одним элементом
  очереди. Поэтому #501 закрывается здесь;
- публикация умеет писать **все одиннадцать** контентных полей, а не пять;
- `pending` отдаёт **404 по прямой ссылке**, а не просто отсутствует в списках;
- куратор может **починить координату** — только у одноточечных объектов, 1119 из 1603;
- **выключение гейта ничего не публикует**, но админ видит счётчик ожидающих и отдельную кнопку
  «опубликовать всё».

Если по ходу реализации найдёшь, что что-то из этого неверно — скажи, а не чини молча. Если это
уровень решения, а не детали, подними `superpowers:brainstorming`.

## Правила, которые действуют всегда

- **Гейты перед каждым коммитом:** `npm run check`, `TEST_REPORT_LOCAL=1 npm test`,
  `npm run test:py`, `/security-check`. Перед пушем — `npm run security:all` и
  `npm run test:e2e:smoke`. Python-гейты на этой машине идут только через Docker
  (`python3.12` отсутствует) — `scripts/require-py-tools.sh` печатает нужную команду.
- **Проверяй код возврата, а не грепай вывод.** `npm run … | tail -40` вернёт код `tail`, и
  красный прогон прочитается как зелёный.
- **Читай файл перед правкой.** Слепые замены по шаблону однажды уничтожили кусок
  `CONTRIBUTING.md`.
- **Никогда `git add -A <dir>`**, если в каталоге есть untracked-файлы.
- **Планы не коммитятся.** `docs/tech/planning/` — локальные рабочие документы. Коммитится
  документация о том, что существует: `docs/tech/`, `docs/vision/vision.md`,
  `docs/security/SECURITY.md`.
- **Проверяй на живой базе, а не на моках.** Замоканный запрос не отличает верный
  пространственный предикат от неверного — ровно так в слайсе C нашлось, что синк уничтожал
  привязки регионов.
- **Думай сначала как эксперт по продукту, потом как инженер.** Мерь на реальных данных: база в
  одном `docker exec`, и она решает вопросы, которые рассуждение не решает.
- Перед PR: ни один коммит не должен существовать только чтобы починить предыдущий коммит той
  же ветки. Складывать через `/pr-changes-amend`.
- Отвечай по-русски; идентификаторы, пути и всё, что уходит в репозиторий, — по-английски.
